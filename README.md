# hubspot_202609 医療機関リスト ホームページURL補完

HubSpotからエクスポートした医療機関リスト（`hubspot_202609.csv`）の
「ウェブサイトURL」列を、Web検索で補完するための手順・スクリプト・成果物。

## 1. 検索条件の指定（効率化のキモ）

医療機関名だけで検索すると、同名施設と医療ポータル（口コミ・予約・求人）が
上位を埋めてしまい、1件あたりの確認コストが跳ね上がる。以下の3点で絞り込む。

### 1-1. クエリ組み立て

    {会社名（分院名まで含めた完全表記）} {市区町村} 公式サイト

- **会社名は分院名まで入れる**：「◯◯クリニック 金山駅前院」のように分院名を落とさない。
  落とすと本院サイトに吸われる。
- **市区町村を必ず添える**：政令市は「名古屋市中村区」のように区まで。
  同名クリニックの誤マッチを最も安く潰せる条件。
- **「公式サイト」を添える**：ポータルより自院ドメインが上がりやすくなる。
- ヒットしない場合の第2クエリ：`"{会社名}" {番地まで含む住所}` を完全一致で。
  それでもダメなら `{会社名} {運営法人名}`（厚生局の届出一覧などから法人名を拾う）。

### 1-2. 除外ドメイン（検索APIの blocked_domains に渡す）

公式HPではないので機械的に除外する。`scripts/dedup_and_query.py` の
`BLOCKED_DOMAINS` に定義。

    byoinnavi.jp / caloo.jp / doctorsfile.jp / fdoc.jp(EPARK) / medimap.jp /
    doctor-map.info / 659naoso.com / qlife.jp / hospita.jp / mrso.jp / itot.jp /
    ekiten.jp / medley.life / byoin.me / indeed.com / guppy.jp / job-medley.com /
    townpage.goo.ne.jp / mapion.co.jp / map.yahoo.co.jp / navitime.co.jp /
    facebook.com / instagram.com / x.com / twitter.com / youtube.com /
    ja.wikipedia.org / hotpepper.jp / e-shops.jp / iryou.jp

なお `iryou.teikyouseido.mhlw.go.jp`（厚労省 医療情報ネット）や
`kouseikyoku.mhlw.go.jp`（届出受理医療機関一覧）は**除外しない**。
公式HPではないが、住所・診療科・医療機関コードの裏取りに使える一次情報源。

### 1-3. 採用判定（誤登録を防ぐ）

検索結果のページに以下のいずれかが一致していれば採用。

| 確度 | 条件 |
|---|---|
| 高 | 施設名が完全一致し、**番地または電話番号**まで元データと一致 |
| 中 | 施設名一致＋市区町村一致だが番地未確認／分院専用サイトが無く運営法人サイトを採用 |
| 低 | 施設名は一致するが所在地の裏取りができていない（要目視確認） |
| 未検出 | 自院HPが存在しないと判断（ポータル掲載のみ） |

「低」は納品前に人の目で1件ずつ確認する前提。

## 2. 重複（同一施設が複数行）の名寄せ

`scripts/dedup_and_query.py` の `dedup_key()` に実装。優先順位は次のとおり。

1. **医療機関コード（正）**（10桁）— これが揃っていれば唯一の同一性判定キー。
   保険医療機関コードは1施設1コードで、改称・移転してもコードは変わらないため、
   会社名の表記ゆれ（法人格の有無、全角半角、スペース）に一切影響されない。
2. コードが欠損している行のみ **郵便番号 + 正規化施設名**
3. それも無ければ **都道府県 + 正規化施設名**

正規化（`norm()`）では「医療法人社団」等の法人格・記号・全角半角を落として比較する。
同一グループ内では「既にURLが入っている行 > レコードIDが新しい行」を代表とし、
代表行にURLを入れて重複行にはグループIDを振る（HubSpot側でマージする際の突き合わせ用）。

先頭54件では重複は0件だった（全件が異なる医療機関コード）。
重複はファイル全体を通してからでないと検出できない。

## 3. スクリプト

    python3 scripts/dedup_and_query.py data/source_head.csv > data/work.csv
    # → 名寄せ結果 + 各行の検索クエリを生成（重複レポートは標準エラーへ）

    python3 scripts/merge_results.py data/work.csv data/found_urls.tsv > data/output.csv
    # → 検索結果を医療機関コードでマージして納品用CSVを生成

## 4. 成果物

| ファイル | 内容 |
|---|---|
| `data/source_head.csv` | 元データ（先頭54件） |
| `data/work.csv` | 名寄せ＋検索クエリ付き |

## 5. 制約（重要）

- **元ファイル全体を取得できていない。** `hubspot_202609.csv` は 14.1MB あり、
  Google Driveコネクタのダウンロード上限（10MB）を超える。
  また当セッションの外向き通信ポリシーで `drive.google.com` への直接アクセスは
  ブロックされているため、APIでの分割取得もできない。
  取得できたのはファイルメタデータに含まれる先頭54件のみ。
- **ページ本文の直接確認ができない。** 任意ドメインへのHTTPアクセスも
  同ポリシーでブロックされる（`sharecli.co.jp` で確認済み）。
  住所照合は検索結果のスニペットに依存しており、これが「確度」の上限になっている。
- 54件中48件を調査した時点でWeb検索のセッション上限に到達。残り6件は未調査。

### 全件処理するには

元CSVを次のいずれかの形で渡してもらう必要がある。

1. **10MB未満に分割**（例：都道府県別 or 2万行ずつ3分割）してDriveに置く
2. **ウェブサイトURLが空の行だけ**に絞ってエクスポートし直す（最も効率が良い）

そのうえで、1件1検索・除外ドメイン付きで機械的に回す。
